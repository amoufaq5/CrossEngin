# R20 — contracts packages: active-active, data-lineage, deploy, edge, finops, migration, pwa, sdk, sdk-clients, files, i18n, search, reporting, views, integrations

## Summary (10 lines max)
- 15 packages, 13,245 non-test source LOC + 16,754 test LOC (193 files). **Zero I/O in any of them**: no `fetch`, no fs, no socket, no SQL, no env read, no storage client (grep over all 15 `src/` trees returned nothing).
- **8 packages (9,229 src LOC / 10,808 test LOC) have ZERO importers anywhere** in `packages/` or `apps/`: active-active, data-lineage, deploy, edge, finops, migration, pwa, sdk-clients.
- 6 are VALIDATION-ONLY (sdk, files, i18n, search, reporting, integrations): what reaches a deployed path is a zod schema/regex embedded in another schema; none of their behaviour functions has a non-test caller. No shipped pack declares `files`/`reports`/`dashboards`/`search`/`integrations`/`i18n`.
- 1 is (narrowly) EXECUTED: `views` — `ListViewSchema` is constructed by the 7 packs and `list-query.ts` reads columns/sort/pageSize. 1 of 8 view kinds.
- Real, executable product in this scope: ~300–400 LOC of 13.2k (≈3%). The rest is typed vocabulary for capabilities that do not exist (CRDT replication, search engine, report engine, file storage, PWA, importers, SDK generator, FinOps, HL7/FHIR).
- The few real algorithms contain real bugs (unreachable today): flag rollout % ineffective, cursor corrupts non-Latin-1 sort values, MV-register is not an MV-register, search permission filter fails open, classification downgrade below co-inputs, sync watermark can never initialise.
- Tests: 1,549 tests, all green by claim; a large share assert enum membership or schema accept/reject. Several test titles claim a count the body does not assert.

## Findings

### R20-01 [Medium] [CONFIRMED] [Correctness / dead code] Feature-flag percentage rollout is ineffective: a variant at N% is served to 100%
- Where: `packages/deploy/src/feature-flags.ts:230-244` (`pickVariant`), `:78-83` (schema allows sum ≤ 100)
- Evidence: schema: `if (totalPercent > 100) {… "must be <= 100"` — sums below 100 are valid. `pickVariant`: `for (const v of variants) { cumulative += v.rolloutPercent; if (bucket < cumulative) return v; } const last = variants[variants.length - 1]; … return last;`. With one variant at `rolloutPercent: 10`, buckets 10–99 fall through to `last` — the same variant.
- Impact: a "10% canary" is a 100% launch. This is the workspace's only `evaluateFlag()`. Unreachable today (package has zero importers) — severity reflects the trap for whoever wires it.
- Fix: fall through to the flag default when `bucket >= cumulative`; or require sum == 100.
- Effort: S

### R20-02 [Medium] [CONFIRMED] [Correctness] SDK cursor codec silently corrupts non-Latin-1 sort values
- Where: `packages/sdk/src/pagination.ts:156-162`
- Evidence: `for (let i = 0; i < json.length; i++) bytes[i] = json.charCodeAt(i) & 0xff;`. Replicated the exact logic in node: `{"lastSortValue":"محمد"}` round-trips to `"E-E/"`, `"€"` to `"¬"`, with no error. Test file has no non-ASCII case (`pagination.test.ts:89-108`).
- Impact: keyset pagination sorted by any Arabic/CJK/€ value resumes from a wrong position — in a product whose v1 locale list is `["en","ar","ar-AE"]`. Also the cursor is unsigned plain JSON. Unreachable: `encodeCursor`/`decodeCursor` have no caller; the server uses three other cursor codecs (`operate-runtime/src/store.ts:237`, `apps/operate-server/src/tenant-manifests.ts:152`, `notification-store.ts:153`).
- Fix: `Buffer.from(json,"utf8").toString("base64url")`; delete the 75-line hand-rolled base64.
- Effort: S

### R20-03 [Medium] [CONFIRMED] [Correctness] `mvRegisterMerge` is a grow-only union, not a multi-value register; LWW merges are not commutative on ties
- Where: `packages/active-active/src/crdts.ts:197-209`, `:162-168`, `:170-186`
- Evidence: `MvRegisterEntrySchema` (`:68-72`) has `value, timestamp, originRegion` — no version vector. Merge: `const merged = [...a.entries]; for (const e of b.entries) { … if (dup === undefined) merged.push(e); }`. Nothing ever removes a causally dominated value, so a register overwritten 1,000 times holds 1,000 "concurrent" values forever. `lwwRegisterMerge`: `return a.originRegion < b.originRegion ? a : b;` — for equal timestamp and equal region with different values, `merge(a,b)=b` and `merge(b,a)=a`. `lwwMapMerge` same tie; `lwwMapGet` uses `find` (first entry) while the schema permits duplicate keys. `mvRegisterMerge` is not imported by `crdts.test.ts` at all (untested).
- Impact: 1 of 6 advertised CRDTs does not have CRDT semantics; 2 are non-convergent on a tie. No replication layer exists, so no data is at risk today. G-counter, PN-counter, OR-set merges and `compareVectorClocks` are correct.
- Fix: per-entry vector clock + dominance pruning; total-order tiebreak including value.
- Effort: M

### R20-04 [Medium] [CONFIRMED] [Security / fail-open, latent] Search permission helpers fail open
- Where: `packages/search/src/permissions.ts:104-108`, `:55-102`
- Evidence: `if (sessionTags.length === 0) return "permission_tags:=*";` — a session with no tags gets a match-everything filter. `isAuthorizedForResource`: role is checked only `if (resourceByKey.has("role"))`, and non-role resource tags (e.g. `department:x`) are ignored unless the caller passes `requireAll` — a resource tagged only with ABAC tags is authorised for everybody by default.
- Impact: contradicts the repo's stated "fail closed" invariant. Not exploitable: no search engine, no caller.
- Fix: empty session → match-nothing filter; require every resource tag key to be satisfied by default.
- Effort: S

### R20-05 [Low] [CONFIRMED] [Correctness] Classification propagation can downgrade below a co-input
- Where: `packages/data-lineage/src/edges.ts:130-156`
- Evidence: `const inputMax = maxSensitivityOf(…)`; then for `anonymized_from` with k≥5: `if (inputMax === "pii_personal") return "public";`. Inputs `[pii_personal, confidential]` → max is `pii_personal` (rank 3 > 2, `nodes.ts:31-38`) → output `public`, below the `confidential` input that anonymisation says nothing about. Same for `aggregated_from`.
- Impact: a derived dataset mixing PII and confidential data is labelled public. Dead code.
- Fix: return max(downgraded PII class, max of non-PII inputs).
- Effort: S

### R20-06 [Low] [CONFIRMED] [Correctness] PWA sync watermark can never be created; client clock decides conflicts
- Where: `packages/pwa/src/sync.ts:132-148`, `:124-130`
- Evidence: `let tenantId = current?.tenantId ?? null;` is never assigned from an operation; `if (maxUpdatedAt === null || entity === null || tenantId === null) return current;` → with `current === null` the function always returns `null`. It also overwrites `entity` with whichever op is newest, so a per-entity watermark changes entity. `applyLastWriteWins` returns `"local"` when `localMs >= serverMs`, i.e. a device with a fast clock always wins.
- Impact: dead code; would break first sync if wired.
- Effort: S

### R20-07 [Low] [CONFIRMED] [Correctness] SDK compatibility: an entry marked `unsupported` is `allowed: true`
- Where: `packages/sdk-clients/src/compatibility.ts:113`
- Evidence: `const allowed = exact.level !== "blocked";` while a *missing* entry returns `{ level: "unsupported", allowed: false }` (`:106-111`). Same level, opposite answers.
- Effort: S

### R20-08 [Low] [CONFIRMED] [Security, latent] Storage key builder validates tenant, prefix and file id but not the extension
- Where: `packages/files/src/storage.ts:44-45`
- Evidence: ``const ext = input.extension !== undefined ? `.${input.extension.replace(/^\./, "")}` : ""; return `t_${input.tenantId}/${input.prefix}${year}/${month}/${input.fileId}${ext}`;`` — `extension: "x/../../t_<other>/a"` yields a key outside the tenant prefix; `parseStorageKey` would reject it but `buildStorageKey` emits it.
- Impact: none today (no object store). Tenant-prefix escape if wired to a path-normalising backend.
- Fix: `/^[A-Za-z0-9]+$/` on the extension.
- Effort: S

### R20-09 [Low] [CONFIRMED] [Correctness] i18n: "ICU MessageFormat parser" is a top-level placeholder extractor with gaps; Hebrew plural table disagrees with the runtime
- Where: `packages/i18n/src/messageformat.ts:89-122`, `:24-37`; `packages/i18n/src/plurals.ts:28`
- Evidence: (a) `parsePlaceholders` jumps `i = close + 1` past each top-level `{…}`, so placeholders nested in plural/select bodies (`{n, plural, one {# by {name}} …}`) are never extracted → `checkPlaceholderConsistency` cannot see a translator dropping `{name}`. (b) No apostrophe quoting: ICU `'{'` literal throws `unbalanced '{'`. (c) Unknown-kind throw rejects legal ICU types (`spellout`, `ordinal`, `duration`). (d) `select` is not required to declare `other`. (e) No formatter exists — nothing turns a message + args into a string. (f) `he: ["one","two","many","other"]` but Node 22.23 here reports `Intl.PluralRules("he")` categories `[one, two, other]`, so `isCompleteForLocale("he", …)` demands a case the runtime never selects. (g) `negotiateAcceptLanguage` does not drop `q=0` entries (`resolution.ts:59-77`). (h) `BCP47_REGEX` (`locales.ts:3`) rejects script subtags and UN M.49 regions (`zh-Hant`, `es-419`).
- Impact: validation-only today (`TenantI18nConfigSchema` in the manifest; no pack declares `i18n`).
- Effort: M
